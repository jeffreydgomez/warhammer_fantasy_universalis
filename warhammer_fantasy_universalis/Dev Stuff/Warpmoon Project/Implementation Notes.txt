THE WARPMOON PROJECT

Initial location: Central Skavenblight, province 4600, owned by U25 at start.
Identifier: war_warpmoon_project. Starts at tier 0; immovable.
All tiers have empty province, area and country modifier blocks.

Owner requirements for construction/upgrading:
- skaven_administration country modifier
- Military Technology >= 12
- trade_goods_produced_amount: warpstone >= 20

Stage       Base ducats       Base months       Base years
1           2000              240               20
2           5000              480               40
3           10000             960               80

These double the common 1000/2500/5000 and 120/240/480 monument values.
Normal national monument cost/time modifiers and construction boosts still work.
The project stays in province 4600. Conquest does not delete the project.

SABOTAGE AND ANNOUNCEMENTS

All countries see Destroy the Warpmoon Project when its exact tier is 1 or 2.
The decision checks the project directly in province 4600.
Its native provinces_to_highlight/Go To points at the current site, even if it
has not been discovered. Its allow condition requires control, not ownership.
Skaven players may use it; Skaven AI has a zero decision weight.

The decision subtracts exactly the current completed tier, leaving the same
project at tier 0 in the same province. It grants 50 prestige and 1000 ducats.
The decision calls hidden country event war_warpmoon.10. Native tier changes
live directly in its immediate block, outside the decision tooltip traversal.
The event rechecks control and the exact tier before changing the project.
It does not destroy/recreate the project or cancel unrelated province activity.
Verify the engine's behavior when sabotage occurs during an upgrade;
the script directly resets completed tiers, not construction progress.

Stages 1 and 2 call hidden province events war_warpmoon.11 and .12. Each
completion, including reconstruction after sabotage, sends the current owner
war_warpmoon.4 or .5 and every OTHER country war_warpmoon.1 or .2. Each country
gets exactly one announcement. All four announcements inherit the province
and current owner as event targets. Navigation in these informational warnings
is an explicit exception requested by the user to AGENTS.md's usual goto rule.

Stage 3 calls hidden province event war_warpmoon.13, whose immediate block
runs all effects in the great project's province scope.
A global flag is set before any effects solely to prevent duplicate detonation
effects. It is not a construction, upgrade, use or sabotage requirement.
destroy_great_project removes the engine; sabotage availability queries the
actual project and its tier.
The current owner, rather than an original builder or occupier, gets the reward.
The current owner receives war_warpmoon.6 after impacts and AE resolve; every
other country receives war_warpmoon.3. Other Skaven countries get the public
announcement too, not the owner's version.
Announcement options have no mechanical effects; delaying/dismissing a popup
cannot delay or repeat the catastrophe.

IMPACTS AND REWARD

Each habitable land province, including uncolonized provinces, rolls separately
at 15%. Seas and impassable wastelands are excluded because they cannot host
normal trade-good production. Exactly these four terrain keys are protected:
underway, dwarf_karak, great_maze, warren_city. Fertile cavern was not added to
the user's explicit exclusion list.

On a hit, all three changes happen together: add_devastation = 100 (clamped by
EU4 to 100), change_trade_goods = warpstone, and a 365-day impact modifier.
The trade good persists. The modifier adds attrition = 100 and max_attrition =
100; the raised cap lets the requested attrition operate beyond the normal 5.
This follows the existing skaven_doomsphere_radiation local-attrition pattern.

We destroyed the Moon is permanent, with yearly prestige = 2, legitimacy = 2,
devotion = 2, horde_unity = 2, republican_tradition = 1, tolerance_own = 2 and
religious_unity = 0.15. The user clarified that prestige should be YEARLY.
Government-resource modifiers apply according to the current government.

Every other country without skaven_administration gets 50 AE opinion against
the firing country. apply_calc = no prevents religion, distance, or AE modifiers
from altering that value. Skaven administration also defines the AI exemption.

BALANCE AND LORE REFERENCES

Dev Stuff/Examples/Balance Guide.txt was consulted before implementation.
Its Weighing Values give the permanent modifier 13.33 prestige + 13.33 applicable
legitimacy/devotion/horde unity + 10 tolerance + 10 unity = 46.67, or 53.33 when
republican tradition (20) applies instead. The 50 prestige sabotage reward is
worth 2; an impact's 100 devastation is worth -4. Local attrition and its cap,
flat ducat amounts, changing trade goods, project removal and AE have no fixed
guide valuation. These are user-specified effects, not random-event options,
and their magnitudes are preserved rather than rebalanced into random events.

Dev Stuff/Examples/Lore Reference.txt, especially the Skaven and Lizardmen
sections, informed the flavor. The End Times: Thanquol's Warpmoon Project and
Morskittar Engine provide the canonical premise. This implementation follows
the user's alternate outcome: dispersed global impacts rather than the
canonical Slann intervention and concentrated destruction of Lustria.
Any eligible Skaven state may complete it; named historical engineers are not
required. Dedicated generated art supplies the monument and event pictures.
The monument uses great_project_war_warpmoon_project.dds (300x150 RGBA8).
Its artwork is fitted into a 290x142 inset at (5, 4), then the exact existing
Dev Stuff/Image Reference/Monument_Image_Template.png is alpha-composited over
it. This preserves the standard gold border, transparent outer edges and dark
title backing. The original generated source remains unchanged.
The first two warnings use WAR_WARPMOON_CONSTRUCTION_eventPicture.dds, showing
the unfinished cannon, exposed coils, scaffolding and suspended muzzle ring.
Only the final-stage events (.3 and .6) use WAR_WARPMOON_eventPicture.dds,
showing the moon shot. Owner events .4 and .5 use the construction picture.
Both event textures are 512x132 DXT1, defined in interface/war_eventpictures.gfx.
Source PNGs, exact built-in image_gen prompts,
export script and decoded previews are preserved in the neighboring Art folder.

VALIDATION

Run: python3 "Dev Stuff/Warpmoon Project/validate_warpmoon.py"

The script extracts the Warpmoon entry from 01_old_world_monuments.txt and
parses the focused scripts. It checks localisation BOM/links, art references,
event-ID uniqueness, blank passive modifiers, costs, and requested reward values.
Its small interpreter exercises the actual scripted triggers/effects against
the fixed site, owner changes, occupation, Skaven/non-Skaven decision eligibility,
zero-tier resets, reconstruction, exclusive owner/public broadcasts, impact
hits/misses, existing devastation,
uncolonized land, all four immunities, AE direction and duplicate detonation.
It also verifies that decision/upgrade tooltips cannot traverse native project
changes, world scans or unsaved event targets, including through hidden_effect.
These checks are not an EU4 engine or UI integration test.

CRASH DIAGNOSIS (2026-10-23)

The eu4_20261023_131637 exception report identifies
CAddGreatProjectTierEffect::GetDesc beneath CHiddenEffect::GetCompleteDesc and
CDecision::GetEffectDescription. Thus hidden_effect did not prevent the native
tier-effect description from crashing on hover. Tier changes now live directly
in war_warpmoon.10 immediate, rather than a scripted-effect expansion in the
decision. The installed 1.37.5 binary also shows GetDesc dereferencing its project
type before formatting the tier; the trace alone does not prove negative tiers
were the cause. Exact -1/-2 changes remain necessary to preserve the tier-0 site.

Upgrade effects similarly call hidden province events, so their previews cannot
resolve event targets that only exist after execution. This also addresses the
repeated undefined war_warpmoon_builder entries in the existing error.log.
All hidden helpers execute without a day delay. Visible event options remain
informational; rewards and catastrophe effects do not depend on clicking them.

   picture, no passive benefits, upgrade costs and times.

   Verify only the current owner receives the permanent modifier, everyone is

7. Save/reload after detonation; the project must remain destroyed and cannot
   fire again. Review fresh error.log for war_warpmoon or related parse errors.

Existing campaigns may require a fresh start to instantiate the newly defined
great project. No save-game migration or automatic construction cheats are added.
